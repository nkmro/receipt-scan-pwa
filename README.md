# 영수증 스캔 PWA

영수증을 구분(경비·접대비·회의비·출장비)별로 촬영해 보관함에 모으고, AI가 날짜·금액·가맹점·결제 수단을 읽어 채운 뒤, 청구할 때 인트라넷 양식에 맞춘 A4 청구본 PDF(갑지 + 영수증)로 만들어 본인 Google Drive에 저장하는 사내 앱입니다.

- 앱 주소: https://nkmro.github.io/receipt-scan-pwa/
- 현재 버전: v0.19.2 (홈 화면 맨 아래에 표시)
- 관리자: 주재홍 (사용자 승인, 법인카드 목록 관리)
- 설계서: Claude 문서 "영수증 스캔 PWA · 1단계 설계서" (설계서 · 데이터·API 스펙 · 화면 스펙 탭)

---

## 1. 전체 구조

```
[직원 폰의 앱(PWA)]  ── GitHub Pages(nkmro.github.io)에서 받음
   │  ① Google 로그인(직원 본인 Gmail)
   │  ② 사진·PDF·시트는 "직원 본인 Drive"에 바로 저장 (drive.file 권한: 앱이 만든 파일만 보임)
   │
   ├──▶ [중계 서버] Cloud Run 함수 receipt-scan-relay (GCP 프로젝트 nkmro-receipt-scan, 서울)
   │       · 로그인 토큰 교환(client secret 보관)    · 사용자 승인(관리자 승인제)
   │       · 법인카드 목록 배포                     · AI 판독 중계(DeepSeek API 키 보관)
   │       · 저장소: Firestore users/{이메일}, config/corpCards
   │
   └──▶ [DeepSeek] deepseek-flash 모델 (중계 서버만 호출. 사진은 서버에 저장하지 않음)
```

- 회사 서버나 공용 DB에는 영수증이 쌓이지 않습니다. 각 직원의 영수증·시트·PDF는 그 직원의 Google Drive에만 있습니다.
- 서버에는 "누가 승인됐는지"와 "법인카드 목록"만 있습니다.

## 2. 직원 Drive에 만들어지는 것

```
내 드라이브/영수증 스캔/
  ├─ 원본/2026-10/        촬영한 영수증 사진(JPEG)·첨부 PDF
  ├─ 청구본/2026-10/      만든 청구 PDF (예: 261031_경비_영수증_주재홍.pdf)
  ├─ 백업/                영수증 장부 백업(하루 1개, 최근 15개) · 관리자는 서버자료 JSON도
  └─ 영수증 장부 (구글 시트)
        ├─ 영수증  영수증·첨부 1건 = 1줄, A~AL 38열 (스키마 7판)
        ├─ 예산    접대비·회의비 기본 월 예산 / 전월 이월 / 추가 예산
        ├─ 설정    내 정보: 사번·팀명·사원명·회사명·승인자·차량번호·회사 차량
        ├─ 카드    AI가 읽은 카드 번호 → 사용자가 고른 결제 수단(카드 기억)
        └─ 메타    B1 = 스키마 버전
```

PC에서 시트를 직접 고쳐도 됩니다(앱은 열 때마다 시트를 다시 읽음). 단, 열 순서와 탭 이름은 바꾸지 마세요.

## 3. 저장소 구조

| 경로 | 역할 |
|---|---|
| `index.html` | 앱 틀. 스크립트·CSS를 `?v=숫자`로 불러옴 |
| `sw.js` | 오프라인 캐시(캐시 이름 `receipt-scan-v숫자`) |
| `manifest.webmanifest`, `icons/` | 홈 화면 앱 이름·아이콘 |
| `privacy.html` | 개인정보 처리방침 |
| `css/app.css` | 전체 디자인 |
| `js/config.js` | 중계 서버 주소, OAuth 클라이언트 ID(공개값) |
| `js/auth.js` | Google 로그인, 토큰 갱신, 승인 확인, 서버 호출 |
| `js/store.js` | Drive 폴더·시트 만들기, 시트 읽기/쓰기, 예산·카드·설정 탭, 백업 |
| `js/imaging.js` | 사진 보정(테두리·흑백·회전) |
| `js/queue.js` | 업로드 대기열(폰 저장 → Drive → 시트), 오프라인 대응 |
| `js/ocr.js` | AI 판독(판독대기 → 보관중/확인필요), 카드 기억 적용 |
| `js/capture.js` | 촬영 화면 |
| `js/box.js` | 보관함(보관중·청구완료·제외), 선택·제외·삭제·되돌리기 |
| `js/detail.js` | 영수증 상세(결제·인트라넷 청구 내역·카드 판독 정보) |
| `js/layout.js` | A4 배치 계산 |
| `js/preview.js` | A4 미리보기, 필수 항목 검사, PDF 만들기 |
| `js/pdf.js` | PDF 작성, 암호 PDF 풀기(pdf.js), PDF 합치기(pdf-lib) |
| `js/gapji.js` | 갑지(사용내역서) 그리기 |
| `js/attach.js` | 파일 첨부(통신비 내역서 등 수동 1건) |
| `js/app.js` | 화면 전환, 홈·예산·내 정보·관리자 화면, 판독·백업 실행 |
| `server/` | 중계 서버 소스(Cloud Run 함수). **이 폴더는 콘솔에 배포된 코드의 사본** |

외부 라이브러리: pdf-lib 1.17.1, pdfjs-dist 3.11.174 — 필요할 때만 jsdelivr에서 무결성(SRI) 확인 후 불러옴.

## 4. 영수증 상태

| 상태 | 뜻 | 다음 |
|---|---|---|
| 업로드 대기 | 폰에만 있음(인터넷 끊김 등) | 연결되면 자동 업로드 |
| 판독대기 | 시트에 올라감, AI 판독 전 | 앱이 열려 있으면 자동 판독 |
| 확인필요 | AI가 확신 못함·처음 보는 카드·판독 3번 실패 | 상세에서 확인·선택 후 저장 → 보관중 |
| 보관중 | 청구할 수 있음 | 체크 → A4 미리보기·PDF |
| 청구완료 | PDF로 청구함 | 다시 만들기 / 되돌리기(PDF는 휴지통) |
| 제외 | 청구하지 않음 | 복원 / 영구 삭제 |

홈 합계: 제외만 빼고 금액이 있는 영수증 모두 포함(확인필요 포함, 건수는 따로 표시).

## 5. 업데이트(배포) 방법

앱(GitHub Pages)
1. 고친 파일을 GitHub 웹의 "Upload files"로 올림(`js/`, `css/`, 루트 순서).
2. **`index.html`의 `?v=숫자`와 `sw.js`의 `receipt-scan-v숫자`를 함께 1 올림.** 안 올리면 폰이 옛 버전을 계속 씀.
3. `js/app.js`의 `APP_VERSION`도 올림(홈 맨 아래 표시).
4. 1~2분 뒤 https://nkmro.github.io/receipt-scan-pwa/ 에 반영. 폰에서는 앱을 **완전히 닫고 다시 열기 2번**.

중계 서버(Cloud Run)
1. Cloud Run 콘솔 → `receipt-scan-relay` → 소스 → [소스 수정] → `index.js` 수정 → [저장 및 재배포].
2. **같은 내용을 GitHub `server/index.js`에도 올림.** (콘솔에서만 고치면 사본이 낡아 복구용으로 못 씀)
3. 환경변수·비밀은 "컨테이너 → 변수 및 보안 비밀"에서. 비밀값은 Secret Manager에 두고 버전을 고정.

| 서버 설정 | 값 |
|---|---|
| GOOGLE_CLIENT_ID | OAuth 클라이언트 ID |
| GOOGLE_CLIENT_SECRET | Secret Manager `google-client-secret` (버전 1) |
| ADMIN_EMAILS | 관리자 Gmail(쉼표 구분) |
| DEEPSEEK_API_KEY | Secret Manager `deepseek-api-key` (버전 1) |
| DEEPSEEK_MODEL | 비우면 deepseek-flash |
| OCR_DAILY_LIMIT | 비우면 계정당 하루 300장 |

비밀을 새로 만들면 서버 계정(`727664895919-compute@developer.gserviceaccount.com`)에 그 비밀의 "Secret Manager 보안 비밀 접근자" 권한을 줘야 배포가 됩니다.

## 6. 백업과 복구

| 무엇 | 어디에 | 언제 | 보관 |
|---|---|---|---|
| 앱 코드·서버 코드 | GitHub `nkmro/receipt-scan-pwa` (커밋 기록 전체) | 배포할 때마다 | 영구 |
| 직원별 영수증 장부(시트 전체 탭) | 각자 Drive `영수증 스캔/백업/영수증 장부_백업_YYYY-MM-DD` | 하루 한 번, 그날 앱을 처음 열 때 | 최근 15개 |
| 서버 자료(사용자 승인 목록·법인카드 목록) | 관리자 Drive `영수증 스캔/백업/서버자료_백업_YYYY-MM-DD.json` | 하루 한 번, 관리자가 앱을 열 때 | 최근 15개 |
| 영수증 사진·청구 PDF | 각자 Drive 원본·청구본 폴더 | 촬영·청구 때 | 원본이 곧 보관본 |

복구
- **시트가 망가졌을 때:** Drive `백업` 폴더의 가장 최근 `영수증 장부_백업_…`을 열어 내용을 원래 `영수증 장부`에 복사해 붙여넣음(탭 이름·열 순서 그대로). 원래 시트를 지우고 백업 파일로 바꾸는 방식은 앱이 못 찾으니 쓰지 않음.
- **청구 PDF를 잘못 지웠을 때:** Drive 휴지통(30일 안).
- **서버(Firestore)가 비었을 때:** 최근 `서버자료_백업_….json`을 보고 관리자 화면에서 사용자 승인·법인카드 목록을 다시 입력.
- **앱이 이상할 때:** GitHub 커밋 기록에서 이전 버전 파일을 다시 올리고 버전 숫자를 올림.

## 7. 자주 생기는 문제

| 증상 | 원인·해결 |
|---|---|
| 고쳤는데 폰에 반영 안 됨 | `?v=`·캐시 이름을 안 올림 → 올리고 앱 완전 종료 2번 |
| "AI 판독이 아직 준비되지 않았습니다" | 서버에 DeepSeek 키 없음/권한 없음 → 5장 서버 설정 확인. 5분 뒤 자동 재시도 |
| "AI 판독 오류(402)" | DeepSeek 계정 잔액 부족 가능성 → platform.deepseek.com 확인 |
| "오늘 판독 횟수를 다 썼습니다" | 계정당 하루 300장 상한 → 직접 입력 또는 다음 날 |
| 승인 대기 화면에서 안 넘어감 | 관리자가 앱 [사용자 승인]에서 승인 → [다시 확인] |
| PDF를 만들 수 없음(빈 칸) | 구분별 필수 항목 미입력 → 미리보기의 빈 칸 목록을 눌러 상세에서 채움 |
| 서버 배포 실패 "Permission denied on secret" | 서버 계정에 비밀 접근자 권한 없음 → 5장 마지막 줄 |
